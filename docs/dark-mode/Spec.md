# 1. 需求背景

- **需求类型**: ☑ 用户反馈 ☑ 战略规划（体验补强）— 属体验缺口补强，任务未提供量化数据支撑。
- **背景 / 驱动**: 界面当前仅有浅色主题，底色为暖白（`rice-50 #fffdf8` / `rice-100 #fbf5ea`）。夜间门店、暗光房间或投屏演示场景下亮度刺激明显，使用者无法主动降低界面亮度，导致视觉疲劳。应用已有「html class + localStorage + 顶栏开关」的偏好实现先例（老人模式），具备低成本落地条件。
- **用户价值**: 让顾客在暗光环境下舒适完成点单到结账的全链路；让演示者在暗光环境获得可读、不刺眼的演示界面。
- **关联重点特性**: 老人模式（`elderly-mode`）、多语言（`i18nextLng`）——本次主题偏好需与其共存且互不干扰。

| 用户角色 | 核心场景 | 痛点 | 相关 SA |
|----------|----------|------|---------|
| 到店顾客 | 夜间/暗光环境用手机浏览菜单、下单、查看履约、结账 | 高亮底色刺眼，长时间浏览视觉疲劳 | REQ-001 ~ REQ-003 |
| 门店演示者 | 暗光会议室演示完整链路（含演示控制台） | 屏幕过亮、投屏刺眼 | REQ-001、REQ-003 |
| 无障碍需求用户 | 需要同时使用老人模式与深色主题 | 两者叠加时样式可能互相干扰、对比度下降 | REQ-004 |

# 3. 核心概念

| 概念 / 术语 | 描述 | 备注 |
|-------------|------|------|
| 主题（Theme） | 界面的一整套配色基调，取值仅「浅色」或「深色」 | 不存在第三态或中间态（R1） |
| 夜间模式 | 用户可见名称，指代深色主题（D-5 已确认口径） | 不使用「深色模式」「暗黑模式」等混用表述 |
| 主题偏好 | 用户对主题的选择，独立于业务状态持久化在本地 | 与其他偏好项互不覆盖（R12） |
| 默认主题 | 无持久化值（首次访问/清除数据）时渲染的主题 = **浅色** | D-3 已确认，不跟随系统偏好 |
| 全站覆盖 | 深色主题同时作用于全部视图与弹窗，无局部浅色残留 | D-2 已确认范围 |
| 主题入口 | 顶栏图标按钮组内、与老人模式相邻的唯一图标按钮 | D-1 已确认；`bind`/`welcome` 无顶栏故无入口（假设 A1） |
| 老人模式 | 既有偏好：放大字号并增强部分半透明文字对比度 | `src/hooks/useElderlyMode.ts` |
| 首屏闪烁（FOUC） | 刷新后先渲染浅色再切换为已保存主题造成的可见闪烁 | 表现要求，见 NFR-004 与假设 A2 |

# 5. 功能需求

> 每条需求独立、可测试、可追溯，采用 EARS 句式。验收编号 `AC-*` 对应《需求澄清》第 5 章。

## REQ-001: 主题切换入口与即时切换

**User Story**
> As a 到店顾客或门店演示者, I want 在界面中一键切换浅色/深色主题, so that 暗光环境下界面不刺眼且仍可正常操作。

**Priority**: P0

**需求描述**
在顶栏图标按钮组中提供**全站唯一**的主题切换入口（图标按钮，具备可访问名称与当前状态标识）。用户点击后在浅色与深色之间切换，配色即时变化，当前视图与业务状态不变，且不产生任何提示。`bind` / `welcome` 视图不渲染顶栏，故不提供切换入口，仅按主题渲染。

**Acceptance Requirements**
- **REQ-001.1**: The system **shall** 在 `TopBar` 图标按钮组内、与老人模式按钮相邻处提供唯一的主题切换入口，且不新增悬浮按钮、设置页/弹窗入口或页面。
- **REQ-001.2**: **When** 用户点击主题切换入口, the system **shall** 在既有 250ms 过渡内完成浅色深色切换，无需刷新。
- **REQ-001.3**: The system **shall** 使入口的可访问名称随当前主题变化（浅色态「切换至夜间模式」，深色态「切换至浅色模式」）并提供 zh/en 双语文案（key 建议 `common.aria_theme_light` / `common.aria_theme_dark`）。
- **REQ-001.4**: **When** 用户切换主题, the system **shall** 保持当前视图、购物车条目、订单项与服务请求不变，且不发起任何网络请求。
- **REQ-001.5**: **If** 用户连续快速切换主题, **then** the system **shall** 保持最终状态与最后一次操作一致，不出现中间态或样式错乱。
- **REQ-001.6**: The system **shall** 在主题切换时不弹出阻断式提示，也不写入全局提示条（`state.lastMessage`）。
- **REQ-001.7**: The system **shall** 以图标状态（图标形态或颜色高亮）区分当前主题，不使用文字标签扩张顶栏布局。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 进入应用并绑定桌台 | 按当前主题渲染，顶栏出现主题切换入口 |
| 2 | 点击主题切换入口 | 界面配色即时切换为另一主题，入口状态标识同步变化，无提示 |
| 3 | 继续点单/查看订单 | 业务操作不受影响，配色保持所选主题 |

**关联埋点**: 本次无埋点需求（演示应用无埋点体系）。
**实现映射**: Design §（待技术设计节点填写）, Tasks T-001

## REQ-002: 主题偏好本地持久化

**User Story**
> As a 到店顾客, I want 主题选择被记住, so that 我下次进入或刷新后不必重复设置。

**Priority**: P0

**需求描述**
主题偏好写入本地持久化存储，刷新或重新进入后按该值渲染（首屏即生效）；读取/写入失败时静默降级为内存态；值非法或缺失时回退默认主题（浅色）。

**Acceptance Requirements**
- **REQ-002.1**: **When** 用户切换主题, the system **shall** 将主题偏好写入本地持久化存储。
- **REQ-002.2**: **When** 用户刷新页面或重新进入应用, the system **shall** 按持久化值渲染主题，且首屏可见范围内无明显浅色闪烁。
- **REQ-002.3**: **If** 本地持久化不可用（隐私模式/禁用存储）, **then** the system **shall** 保持本次会话内切换有效并静默降级，不报错、不阻塞、不提示。
- **REQ-002.4**: **If** 持久化值为非法值或缺失, **then** the system **shall** 按默认主题（浅色）渲染，界面无错乱。
- **REQ-002.5**: The system **shall** 使用与 `i18nextLng`、`elderly-mode` 相互独立的持久化项，不覆盖上述既有值。
- **REQ-002.6**: The system **shall** 在 React 挂载前完成主题态初始化，避免刷新出现可见的浅色闪烁（参考 `index.html` 现有语言初始化内联脚本的做法）。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 切换为深色 | 界面即时变深色，本地保存深色偏好 |
| 2 | 刷新页面 | 首屏以深色渲染，无可见闪烁 |
| 3 | 清除站点数据后进入 | 以浅色（默认主题）渲染 |

**关联埋点**: 无。
**实现映射**: Design §（待填）, Tasks T-002

## REQ-003: 深色主题全站视觉覆盖与可读性

**User Story**
> As a 暗光环境下的使用者, I want 深色主题下全站内容清晰可读, so that 我能无障碍完成从绑桌到结账的完整流程。

**Priority**: P0

**需求描述**
深色主题作用于全部视图与弹窗（D-2 全站覆盖）：页面底色、卡片、文字、按钮、表单、导航、分割线、噪点纹理与选中态均切换为深色等价表现，且满足对比度要求；同时同步 `theme-color`。

**Acceptance Requirements**
- **REQ-003.1**: The system **shall** 在深色主题下为 `bind`、`welcome`、`menu`、`order`、`checkout` 全部视图及全部弹窗、移动端底部导航渲染深色等价配色，无局部浅色残留（含 `paper-noise` 纹理）。
- **REQ-003.2**: The system **shall** 保证深色主题下正文文字与背景对比度 ≥ 4.5:1，大号文字与图形元素 ≥ 3:1。
- **REQ-003.3**: The system **shall** 保证深色主题下按钮、输入框、弹窗关闭入口等交互元素可见、可点击、可聚焦（焦点态可辨识）。
- **REQ-003.4**: The system **shall** 在深色主题下仅改变颜色相关属性，不改变字号、间距、圆角、布局与动画时长。
- **REQ-003.5**: **If** 某处现有色值在深色底上无法满足对比度要求, **then** the system **shall** 在深色下使用等价替代色阶，且不新增品牌色系或引入第三方主题。
- **REQ-003.6**: **When** 深色主题生效, the system **shall** 将 `theme-color` 同步为与深色底色一致的深色值；**When** 切回浅色, the system **shall** 恢复为 `#fbf5ea`。

**用户交互**

## REQ-005: 降级与兼容

**User Story**

| 1 | 在禁用存储的浏览器中切换主题 | 界面即时切换，无报错提示，刷新后回到浅色 |
| 2 | 手动写入非法持久化值后访问 | 以浅色渲染，界面正常 |
| 3 | 系统为深色偏好时首次访问 | 仍以浅色渲染（不跟随系统） |
