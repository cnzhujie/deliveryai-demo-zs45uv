# 1. 需求背景

- **需求类型**: ☑ 用户反馈 ☑ 战略规划（体验补强）— 属体验缺口补强，任务未提供量化数据支撑。
- **背景 / 驱动**: 界面当前仅有浅色主题，底色为暖白（`rice-50 #fffdf8` / `rice-100 #fbf5ea`）。夜间门店、暗光房间或投屏演示场景下亮度刺激明显，使用者无法主动降低界面亮度，导致视觉疲劳。应用已有「html class + localStorage + 顶栏开关」的偏好实现先例（老人模式），具备低成本落地条件。
- **用户价值**: 让顾客在暗光环境下舒适完成点单到结账的全链路；让演示者在暗光环境获得可读、不刺眼的演示界面。
- **关联重点特性**: 老人模式（`elderly-mode`）、多语言（`i18nextLng`）——本次主题偏好需与其共存且互不干扰。

| 用户角色 | 核心场景 | 痛点 | 相关 SA |
|----------|----------|------|---------|
| 到店顾客 | 夜间/暗光环境用手机浏览菜单、下单、查看履约、结账 | 高亮底色刺眼，长时间浏览视觉疲劳 | REQ-001 ~ REQ-003 |
| 门店演示者 | 暗光会议室演示完整链路（含演示控制台） | 屏幕过亮、投屏刺眼 | REQ-001、REQ-003 |
| 无障碍需求用户 | 需要同时使用老人模式与深色主题 | 两者叠加时样式可能互相干扰、对比度下降 | REQ-004 |

# 2. 目标与边界

## 2.1 目标

| 目标 ID | 类目 | 目标描述 | 可度量指标 | 目标值 |
|---------|------|----------|------------|--------|
| GOAL-001 | 用户 | 可显式切换浅色/深色主题，切换即时生效 | 点击入口后界面配色变化是否即时发生（无需刷新） | 100% 立即生效（≤ 既有 250ms 过渡） |
| GOAL-002 | 用户 | 深色主题下核心页面与弹窗可读可操作 | 正文对比度 / 大号文字与图形对比度 | ≥ 4.5:1 / ≥ 3:1（WCAG 2.1 AA） |
| GOAL-003 | 用户 | 主题偏好在刷新或再次进入后保持一致 | 刷新后主题与切换前一致的比例 | 100%（`localStorage` 可用时） |
| GOAL-004 | 用户 | 浅色模式与既有功能零回归 | 既有 E2E 用例通过率；浅色模式视觉差异 | 100% 通过；浅色视觉无差异 |
| GOAL-005 | 技术 | 不引入新依赖、不新增网络请求、不改业务状态机 | 新增依赖数；主题切换触发的网络请求数 | 0；0 |

# 3. 核心概念

| 概念 / 术语 | 描述 | 备注 |
|-------------|------|------|
| 主题（Theme） | 界面的一整套配色基调，取值仅「浅色」或「深色」 | 不存在第三态或中间态（R1） |
| 夜间模式 | 用户可见名称，指代深色主题（待确认命名口径，Q5） | 任务描述用语 |
| 主题偏好 | 用户对主题的选择，独立于业务状态持久化在本地 | 与其他偏好项互不覆盖（R12） |
| 默认主题 | 无持久化值（首次访问/清除数据）时渲染的主题，默认浅色 | 待确认是否跟随系统偏好（Q2） |
| 全站覆盖 | 深色主题同时作用于全部视图与弹窗，无局部浅色残留 | 范围结论待确认（Q3） |
| 老人模式 | 既有偏好：放大字号并增强部分半透明文字对比度 | `src/hooks/useElderlyMode.ts` |
| 首屏闪烁（FOUC） | 刷新后先渲染浅色再切换为已保存主题造成的可见闪烁 | 表现要求，见 NFR-004 |

# 5. 功能需求

> 每条需求独立、可测试、可追溯，采用 EARS 句式。验收编号 `AC-*` 对应《需求澄清》第 5 章。

## REQ-001: 主题切换入口与即时切换

**User Story**
> As a 到店顾客或门店演示者, I want 在界面中一键切换浅色/深色主题, so that 暗光环境下界面不刺眼且仍可正常操作。

**Priority**: P0

**需求描述**
在顶栏图标按钮组中提供主题切换入口（图标按钮，具备可访问名称与当前状态标识）。用户点击后在浅色与深色之间切换，配色即时变化，当前视图与业务状态不变。`bind` / `welcome` 视图是否提供入口取决于覆盖范围结论（Q1/Q3）。

**Acceptance Requirements**
- **REQ-001.1**: The system **shall** 在 `TopBar` 图标按钮组内提供唯一的主题切换入口，且不新增悬浮按钮或页面。
- **REQ-001.2**: **When** 用户点击主题切换入口, the system **shall** 在既有 250ms 过渡内完成浅色↔深色切换，无需刷新。
- **REQ-001.3**: The system **shall** 使入口的可访问名称随当前主题变化（浅色态「切换至夜间模式」，深色态「切换至浅色模式」）并提供中英双语文案。
- **REQ-001.4**: **When** 用户切换主题, the system **shall** 保持当前视图、购物车条目、订单项与服务请求不变，且不发起任何网络请求。
- **REQ-001.5**: **If** 用户连续快速切换主题, **then** the system **shall** 保持最终状态与最后一次操作一致，不出现中间态或样式错乱。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 进入应用并绑定桌台 | 按当前主题渲染，顶栏出现主题切换入口 |
| 2 | 点击主题切换入口 | 界面配色即时切换为另一主题，入口状态标识同步变化 |
| 3 | 继续点单/查看订单 | 业务操作不受影响，配色保持所选主题 |

**关联埋点**: 本次无埋点需求（演示应用无埋点体系）。
**实现映射**: Design §（待技术设计节点填写）, Tasks T-001

## REQ-002: 主题偏好本地持久化

**User Story**
> As a 到店顾客, I want 主题选择被记住, so that 我下次进入或刷新后不必重复设置。

**Priority**: P0

**需求描述**
主题偏好写入本地持久化存储，刷新或重新进入后按该值渲染；读取/写入失败时静默降级为内存态；值非法或缺失时回退默认主题。

**Acceptance Requirements**
- **REQ-002.1**: **When** 用户切换主题, the system **shall** 将主题偏好写入本地持久化存储。
- **REQ-002.2**: **When** 用户刷新页面或重新进入应用, the system **shall** 按持久化值渲染主题，且首屏可见范围内无明显浅色闪烁。
- **REQ-002.3**: **If** 本地持久化不可用（隐私模式/禁用存储）, **then** the system **shall** 保持本次会话内切换有效并静默降级，不报错、不阻塞。
- **REQ-002.4**: **If** 持久化值为非法值或缺失, **then** the system **shall** 按默认主题渲染，界面无错乱。
- **REQ-002.5**: The system **shall** 使用与 `i18nextLng`、`elderly-mode` 相互独立的持久化项，不覆盖上述既有值。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 切换为深色 | 界面即时变深色，本地保存深色偏好 |
| 2 | 刷新页面 | 首屏以深色渲染，无可见闪烁 |
| 3 | 清除站点数据后进入 | 按默认主题渲染 |

**关联埋点**: 无。
**实现映射**: Design §（待填）, Tasks T-002

## REQ-003: 深色主题视觉覆盖与可读性

**User Story**
> As a 暗光环境下的使用者, I want 深色主题下所有内容清晰可读, so that 我能无障碍完成点单到结账的全流程。

**Priority**: P0

**需求描述**
深色主题作用于全部受范围约束的视图与弹窗（范围结论见 Q3）：页面底色、卡片、文字、按钮、表单、导航、分割线、噪点纹理与选中态均切换为深色等价表现，且满足对比度要求。

**Acceptance Requirements**
- **REQ-003.1**: The system **shall** 在深色主题下为 `bind`、`welcome`、`menu`、`order`、`checkout` 及全部弹窗渲染深色等价配色，无局部浅色残留（含 `paper-noise` 纹理与移动端底部导航）。
- **REQ-003.2**: The system **shall** 保证深色主题下正文文字与背景对比度 ≥ 4.5:1，大号文字与图形元素 ≥ 3:1。
- **REQ-003.3**: The system **shall** 保证深色主题下按钮、输入框、弹窗关闭入口等交互元素可见、可点击、可聚焦（焦点态可辨识）。
- **REQ-003.4**: The system **shall** 在深色主题下仅改变颜色相关属性，不改变字号、间距、圆角、布局与动画时长。
- **REQ-003.5**: **If** 某处现有色值在深色底上无法满足对比度要求, **then** the system **shall** 在深色下使用等价替代色阶，且不新增品牌色系或引入第三方主题。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 在深色下浏览菜单 | 菜品卡片、分类、搜索框文字清晰可读 |
| 2 | 打开规格/风险/服务/控制台弹窗 | 弹窗深色呈现，内容与按钮可读可操作 |
| 3 | 移动端（<1280px）操作 | 底部导航与购物车按钮深色呈现，不遮挡主操作区 |

**关联埋点**: 无。
**实现映射**: Design §（待填）, Tasks T-003

## REQ-004: 主题与老人模式叠加

**User Story**
> As a 需要更大字号与更暗底色的使用者, I want 两个偏好同时生效, so that 我能同时获得对比度与亮度上的改善。

**Priority**: P1

**需求描述**
主题偏好与老人模式相互独立，可同时开启；叠加时以可读性要求为准校准样式，开关状态互不覆盖。

**Acceptance Requirements**
- **REQ-004.1**: The system **shall** 允许深色主题与老人模式同时开启，任一开关不改变另一开关的状态。
- **REQ-004.2**: **When** 两者同时开启, the system **shall** 仍满足 REQ-003.2 的对比度要求，且老人模式的字号放大与触控区域约定继续生效。
- **REQ-004.3**: **If** 老人模式针对浅色背景写死的半透明文字覆盖规则在深色下失效或过度加亮, **then** the system **shall** 为深色 + 老人模式组合提供等价可读的样式规则。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 开启老人模式 | 字号放大、对比度增强（既有行为） |
| 2 | 再切换深色主题 | 深色 + 放大字号；老人模式仍开启 |
| 3 | 关闭主题或老人模式之一 | 仅关闭对应项，另一项状态保持 |

**关联埋点**: 无。
**实现映射**: Design §（待填）, Tasks T-004

## REQ-005: 降级与兼容

**User Story**
> As a 处于受限环境的用户, I want 界面在异常环境下仍可用, so that 存储或系统能力缺失不会破坏点单流程。

**Priority**: P1

**需求描述**
在本地存储不可用、持久化值非法、系统偏好能力不支持等异常下，界面必须保持可用且主题可切换，不得出现白屏、报错或样式错乱。

**Acceptance Requirements**
- **REQ-005.1**: **If** 本地存储不可用, **then** the system **shall** 仍完成主题切换且不报错，刷新后回退默认主题。
- **REQ-005.2**: **If** 持久化值非法, **then** the system **shall** 回退默认主题且无控制台报错。
- **REQ-005.3**: **If** 确认采用「跟随系统偏好」能力且系统能力不可用, **then** the system **shall** 回退默认主题并保持界面可用。
- **REQ-005.4**: The system **shall** 在无持久化值时按默认主题渲染（默认浅色；若确认跟随系统则为系统偏好对应主题）。
