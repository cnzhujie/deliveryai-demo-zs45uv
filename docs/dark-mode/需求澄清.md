# 需求澄清：夜间模式（深色主题）

> 状态：草稿（可评审）｜ 需求来源：工作流任务「添加夜间模式」｜ 澄清日期：2026-09-16
> 适用仓库：`cnzhujie/deliveryai-demo-zs45uv`（产品名 `hdl-order-demo`，沸点火锅点单与门店履约概念演示）
> 配套文档：同目录 `Spec.md`（需求规格）；未确认项见文末「6. 待确认清单」与「附录 B. 人机交互问题」

---

## 1. 一句话概述

在沸点火锅点单演示应用（`hdl-order-demo`）现有界面中新增「夜间模式（深色主题）」及浅色/深色显式切换能力，使使用者在暗光环境下也能舒适阅读与操作界面，同时不改变现有浅色模式表现、信息架构与交互方式，且不引入任何后端依赖。

---

## 2. 背景与目标

### 背景

- **现状（仓库证据）**：应用为 React 18 SPA + Tailwind CSS 3.4，`tailwind.config.js` 未配置 `darkMode`，颜色类名（`bg-rice-100`、`text-charcoal-900`、`bg-chili-500` 等）直接硬编码在组件 JSX 中；`src/index.css` 中 `:root` / `body` 的背景固定为 `#fbf5ea`，`index.html` 固定 `<meta name="theme-color" content="#fbf5ea">`。仓库 `AGENTS.md` 明确记录「单一浅色主题，无暗色模式」「颜色使用上述色板，仅需浅色样式」。
- **场景缺口**：界面整体为暖白高亮底色（`rice-50 #fffdf8` / `rice-100 #fbf5ea`）。在夜间门店、暗光房间或投屏演示场景下，大面积高亮背景造成刺眼与视觉疲劳，缺少可主动降低亮度刺激的手段。
- **触发来源**：产品体验补强（任务描述未提供用户反馈数据、投诉量或业务指标，故不以数据驱动论证）。
- **为什么现在做**：现有应用已有「偏好类开关」的成熟先例——老人模式通过 `src/hooks/useElderlyMode.ts` 实现「html class + localStorage 持久化 + 顶栏图标开关」，主题切换可复用同一模式，改造成本可控、影响面收敛在前端样式层。
- **现有方案为什么不够**：老人模式只放大字号与个别半透明文字对比度，不改变整体亮度基调；浏览器/系统级深色扩展不属于产品可控能力，无法保证本应用配色正确。

### 目标

1. 使用者可在界面中**显式**切换浅色 / 深色主题，切换即时生效，无需刷新或二次确认。
2. 深色主题下核心页面与各弹窗的正文、按钮、表单、导航可读可操作，正文对比度满足 WCAG 2.1 AA（≥ 4.5:1）。
3. 主题偏好本地持久化，刷新页面或再次进入后保持一致。
4. 浅色模式的视觉、布局、交互与既有功能完全不受影响；现有 E2E 用例保持通过。
5. 主题偏好与既有偏好（语言、老人模式）相互独立，可同时生效、互不覆盖。

### 不做（初版边界）

1. 不提供多套自定义配色、主题编辑器、主题市场或按用户/租户下发配色（仅「浅色 / 深色」两态）。
2. 不改造后端接口与业务逻辑，不新增任何后端依赖（含不修改 `server/` 目录）。
3. 不改变现有信息架构、导航结构、页面布局与交互方式（不新增页面、不调整点单/订单/结账流程）。
4. 不覆盖或改写第三方嵌入内容（说明：本仓库未发现第三方嵌入内容，该边界目前无适用对象，见待确认清单 B-4）。
5. 不做定时/自动切换（如日落自动深色）、不做按页面或组件粒度的主题白名单配置（推断为初版外延，待确认）。
6. 不追求深色主题下的品牌视觉再设计：配色在现有色板基础上推导，不新增品牌色系、不引入第三方设计系统。

## 3. 需求详情

### 用户场景

- **主要使用者**：到店扫码点单的顾客（手机端浏览菜单、下单、查看履约、结账）与演示者（在暗光会议室/投屏环境中演示完整链路）。
- **场景 A（夜间点单）**：夜间门店灯光较暗，顾客进入应用（绑桌 → 欢迎页 → 菜单），期望界面以深色呈现，减少亮度刺激后继续点单。
- **场景 B（暗光演示）**：演示者在暗光环境演示「菜单 → 订单 → 结账 + 服务呼叫 + 演示控制台」，期望屏幕不刺眼且文字可读。
- **场景 C（来回切换）**：顾客在深色下完成点单，中途切回浅色查看，再切回深色，期望功能与状态不受影响。
- **前置条件**：浏览器可用（与现有支持范围一致）；`localStorage` 可用时主题跨会话保持，不可用时降级为本次会话有效。

### 用户路径

1. 使用者进入应用：`bind`（绑定桌台）→ `welcome`（欢迎页）→ `menu`（菜单）。
2. 在顶栏（`TopBar`）找到主题切换入口（现有图标按钮组内的图标按钮，具体位置见待确认 B-1）。
3. 点击入口 → 界面配色在既有 250ms 过渡内切换为深色，当前视图、购物车与订单状态保持不变。
4. 在深色下继续点单、查看订单、结账、呼叫服务、打开演示控制台，表现正常。
5. 刷新页面 → 界面仍为深色。
6. 再次点击入口 → 切回浅色，界面恢复与改动前一致的浅色表现。

**异常 / 回退路径**

- 分支 1（存储不可用）：`localStorage` 写入失败（隐私模式、禁用存储）→ 切换仍即时生效，仅本次会话有效；刷新后回到默认主题；不报错、不阻塞（是否提示见待确认 B-4 之外的 B-5）。
- 分支 2（无持久化值）：首次访问或清除站点数据 → 按默认主题渲染（默认浅色；若确认跟随系统偏好则取系统值，见待确认 B-2）。
- 分支 3（无顶栏视图）：`bind` / `welcome` 视图当前不渲染 `TopBar`，这两个视图的入口与主题表现取决于覆盖范围结论（见待确认 B-3）。
- 分支 4（持久化值非法）：存储值为未知字符串 → 回退默认主题，界面无错乱。

### 产品规则

> 一条规则只表达一个约束，便于评审与验收。

- **R1** 界面主题恒为「浅色」或「深色」之一，不存在未定义态或中间态。
- **R2** 主题切换入口位于顶栏现有图标按钮组内（与「呼叫服务 / 会员 / 演示控制台 / 老人模式 / 语言」同组或紧邻），不新增悬浮按钮、不新增页面（推断，待确认 B-1）。
- **R3** 点击入口一次即在浅色与深色之间切换，切换立即生效，无需刷新、无需二次确认。
- **R4** 主题偏好参与本地持久化；持久化值非法或缺失时回退默认主题（键名与实现方式由技术设计确定）。
- **R5** 刷新或重新进入应用时按持久化值渲染主题；无值时按默认主题（默认浅色，若确认跟随系统则取系统偏好，见待确认 B-2）。
- **R6** 主题切换不改变业务状态（当前视图、购物车条目、订单项、服务请求、支付状态），也不发起任何网络请求。
- **R7** 深色主题下正文类文字与其背景对比度 ≥ 4.5:1，大号文字（≥ 18.66px 粗体 / 24px）与图形元素 ≥ 3:1。
- **R8** 深色主题覆盖范围包含全部受本次范围约束的页面与弹窗（范围结论见待确认 B-3）；同一页面内不得出现局部深色、局部浅色的混搭。
- **R9** 主题与老人模式相互独立，可同时开启；两者叠加时以 R7 可读性要求为准进行样式校准，两个开关状态互不覆盖。
- **R10** 浅色模式下的颜色、字号、布局、动效与文案与本次改动前保持一致（零视觉回归）。
- **R11** 切换入口必须具备可访问名称（随语言切换的中英双语），并可区分当前主题状态（图标或高亮状态变化）。
- **R12** 主题偏好与既有偏好使用彼此独立的持久化项（`i18nextLng`、`elderly-mode`、主题项互不覆盖）。

### 状态与反馈

- **成功**：点击入口后界面配色即时切换（既有 250ms 过渡），顶栏入口呈现当前主题状态；流程不被打断，无阻塞式弹窗。
- **失败**：本地持久化写入/读取失败时静默降级为内存态——切换仍即时生效，不报错、不阻塞；刷新后回到默认主题（推断：不额外提示；若产品要求提示，需补文案，见待确认 B-5）。
- **空态**：无持久化值时按默认主题渲染，不出现无主题或配色错乱状态。
- **无权限**：本需求不涉及角色与权限差异，所有使用者均可切换主题（无权限拦截分支）。
- **异常**：当系统偏好读取不支持（`matchMedia` 不可用，仅当确认「跟随系统」时）→ 回退默认主题，界面正常可用；当持久化值非法 → 回退默认主题。
- **保持不变**：浅色模式视觉零变化；业务链路（绑桌 → 欢迎 → 菜单 → 订单 → 结账 → 服务呼叫 → 演示控制台）行为不变；既有 localStorage 键 `i18nextLng`、`elderly-mode` 的语义与默认值不变；`e2e/super-spicy.spec.ts` 全部用例保持通过。

### 关键文案

- **入口可访问名称（aria-label）**：
  - 浅色态：「切换至夜间模式」/ en `Switch to dark mode`
  - 深色态：「切换至浅色模式」/ en `Switch to light mode`
- **切换反馈提示（可选，待确认 B-5）**：`已切换为夜间模式` / `已切换为浅色模式`（en 对应文案）。
- **命名一致性（待确认 B-5）**：入口可见性/状态用「夜间模式」还是「深色模式」，需产品统一口径（本清单按任务描述统一用「夜间模式」指代用户可见名称，「深色」指代技术态）。
- **既有冲突点（非本次新增）**：老人模式按钮的 aria-label 与切换提示为硬编码中文（`src/components/TopBar.tsx` 第 59 行、`src/App.tsx` 第 68 行），未走 i18n；本次新增主题文案建议走 `src/i18n.ts`，是否顺带修复老人模式文案见待确认 B-5。

### 关键表现要求

> 本需求与视觉/交互强相关，故保留本节。以下为可感知层面的要求，具体色值由产品/设计在技术设计阶段确定。

- **过渡节奏**：沿用全局 250ms 色彩过渡（`src/index.css`），切换过程不出现闪白、跳动或布局位移。
- **首屏呈现**：刷新后首屏即按已保存主题渲染，可见范围内无明显的浅色闪烁（FOUC）；实现方式由技术设计决定（推断项，是否作为硬验收见待确认 B-5）。
- **深色基调**：以现有色板推导深色底色与文字色，避免使用纯黑 `#000` 配纯白的高反差组合；品牌红 `chili-500 #e13b2b` 在深色底上的可读性需重新校验，必要时在深色下改用更亮/更暗的等价色阶（不新增品牌色系）。
- **纹理与背景**：`src/App.tsx` 的 `paper-noise` 噪点纹理与 `bg-rice-100` 底色在深色下需改为等价深色表现，不残留浅色噪点。
- **系统 UI 颜色**：`index.html` 的 `theme-color` 固定 `#fbf5ea`，深色下移动端浏览器地址栏/系统 UI 与页面不一致，建议随主题更新（推断项，见待确认 B-5）。
- **干扰控制**：入口不遮挡主操作区与移动端底部导航（`lg:hidden`，当前 4 列）；不改变既有元素尺寸与触控区域（含老人模式 `button` 最小高度约定）。
- **仅颜色变化**：主题切换只影响颜色相关属性，不改变字号、间距、圆角、布局密度与动画时长。

## 4. 约束限制

- **本次不做**：见「2.3 不做」，尤其不引入多套配色/主题编辑器、不新增后端依赖、不改信息架构与业务逻辑。
- **保持不变**：浅色模式视觉零变化；现有 E2E 断言（依赖可见文案与业务 class，如 `border-chili-500`）保持有效；`i18nextLng` / `elderly-mode` 语义不变；`server/` 目录不修改；`src/state/orderReducer.ts` 订单状态机不因主题改动而变化。
- **权限要求**：无角色/权限差异，无灰度开关需求（推断：全量对所有使用者生效；若产品要求灰度，需另提供开关方案）。
- **兼容要求**：兼容现有 Chromium 环境（Playwright 默认 Desktop Chrome 1280×720，移动端场景 390×844）；兼容中英双语；兼容 `localStorage` 不可用环境；持久化值缺失/非法时行为已定义。
- **性能要求**：纯前端样式切换，不发起网络请求；不引入可感知卡顿；过渡时长沿用既有 250ms；不新增运行时重依赖。
- **稳定性要求**：任何存储/配置异常都必须降级为「界面可用 + 主题可切换」，不得出现白屏、控制台报错或样式错乱。
- **实现限制（来自仓库约定，属推断待确认）**：
  - 样式沿用 Tailwind 类名直写，不引入 CSS Modules、styled-components 或新 UI 库；不引入后端 API 调用（`AGENTS.md`「不要做」）。
  - **待裁决冲突**：`AGENTS.md` 明确「颜色类名直接硬编码，不引入 CSS 变量抽象层」，而深色主题常见实现需要 `darkMode: 'class'` + `dark:` 变体，或引入 CSS 变量语义 token 层。两条路径的成本与约定一致性不同，需确认（见待确认 B-3/B-5 之外的附录 B-5 实现路径问题）。
  - `AGENTS.md` 中「单一浅色主题，无暗色模式」「仅需浅色样式」的描述在本次改动后失效，需由代码节点同步更新（属本次范围内的文档同步）。

## 5. 验收标准

> 每条均可由产品、测试、开发共同判断通过；不描述实现细节。

- **[主流程]** 前置：处于已绑定桌台的 `menu` 视图且顶栏可见、当前为浅色主题；使用者点击主题切换入口后，界面配色应即时切换为深色（背景、文字、按钮、导航配色变化），再次点击应切回浅色。
- **[主流程]** 在 `menu` 视图已加入购物车条目的前提下切换主题，当前视图、购物车条目与订单状态不应丢失。
- **[内容正确性]** 切换入口的可访问名称应随当前主题变化（浅色态「切换至夜间模式」，深色态「切换至浅色模式」），并随中英文切换提供对应文案。
- **[内容正确性]** 深色主题下，`bind`、`welcome`、`menu`、`order`、`checkout` 页面及商品规格弹窗、超级辣风险提示弹窗、服务面板、演示控制台、会员弹窗、购物车弹窗中的正文文字与背景对比度应 ≥ 4.5:1，大号文字与图形元素 ≥ 3:1；按钮与输入项可正常点击与输入。
- **[兼容稳定]** 在深色主题下完成一次完整链路（绑桌 → 欢迎 → 菜单下单 → 订单 → 结账），功能与文案应无异常，无不可读或不可操作区域。
- **[边界约束]** 浅色模式下页面外观与本次改动前一致（既有业务 class 与关键文案不变），且 `e2e/super-spicy.spec.ts` 全部用例通过。
- **[兼容稳定]** 深色主题与老人模式同时开启时，界面仍满足对比度要求，字号放大与触控区域约定仍生效，两个开关状态互不覆盖。
- **[兼容稳定]** 切换主题不应产生任何网络请求，且不应改变 `i18nextLng`、`elderly-mode` 的值。
- **[异常处理]** 当 `localStorage` 不可用时，切换主题应仍即时生效且不报错，刷新后回退默认主题。
- **[异常处理]** 当持久化值为非法值（如 `theme=blue` 或空串）时，系统应按默认主题渲染，界面无错乱。
- **[主流程]** 选择深色后刷新页面，页面应仍为深色，且首屏可见范围内无明显浅色闪烁。
- **[边界约束]** 清除站点数据后首次进入应用，应按默认主题渲染（默认浅色；若确认跟随系统偏好，则为系统偏好对应主题）。
- **[兼容稳定]** `npm run build`、`npm run lint`、`npx tsc -b --noEmit` 应全部通过，且未新增依赖。
